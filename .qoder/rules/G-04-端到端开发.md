# G-04: 端到端开发

## 后端流程（Go）

```
Step 1: 定义 Model
├── 读取现有 model/ 目录结构
├── 创建 model/{resource}.go
└── 确认字段类型、索引、标签

Step 2: 创建 Repository
├── 读取现有 repository/ 模式
├── 创建 repository/{resource}_repo.go
├── 实现 CRUD 方法
└── 确认上下文传递、错误处理

Step 3: 创建 Service
├── 读取现有 service/ 模式
├── 创建 service/{resource}_service.go
├── 实现业务逻辑
├── 事务处理（如需要）
└── 调用 Repository

Step 4: 创建 Handler
├── 读取现有 handler/ 模式
├── 创建 handler/{resource}_handler.go
├── 实现 HTTP 接口
├── 参数绑定、校验
└── 调用 Service

Step 5: 注册 Router
├── 读取 router/ 注册方式
├── 添加路由组
├── 注册 CRUD 路由
└── 配置中间件（auth 等）

Step 6: 创建 DTO（如需要）
├── 定义 Request/Response 结构
└── 实现转换函数
```

## 后端流程（Python）

```
Step 1: 定义 Model
├── 创建 package/models/{entity}.py
└── 用 dataclass 或 Pydantic，标注类型

Step 2: 实现 Service
├── 创建 package/services/{entity}_service.py
├── 核心业务逻辑
└── 不直接操作 DB/IO，通过 adapter

Step 3: 实现 Adapter（如有外部调用）
├── 创建 package/adapters/{entity}_adapter.py
└── 封装外部 API / DB 访问

Step 4: 接入 CLI 或 API
├── CLI: cli/commands/ 下新增命令
├── API: server/ 下注册路由
└── 只做参数绑定和调用 service
```

## 前端流程（Vue）

```
Step 1: 定义 TS 类型
├── 读取 types/ 目录结构
├── 创建 types/{resource}.ts
└── 与后端 Response 保持一致

Step 2: 创建 API 函数
├── 读取 api/ 目录模式
├── 创建 api/{resource}.ts
├── 实现 CRUD 接口
└── 统一错误处理

Step 3: 创建 Composable
├── 读取 composables/ 模式
├── 创建 composables/use{Resource}.ts
├── 封装状态管理
└── 实现加载、错误状态

Step 4: 创建组件
├── 列表组件：{Resource}List.vue
├── 表单组件：{Resource}Form.vue
├── 详情组件：{Resource}Detail.vue（如需要）
└── 遵循 Vue 组件规范

Step 5: 创建页面
├── 创建 views/{resource}/ 目录
├── 列表页：index.vue
├── 创建/编辑页：create.vue / edit.vue
└── 详情页：detail.vue（如需要）

Step 6: 注册路由
├── 读取 router/ 结构
├── 添加路由配置
├── 配置权限（meta.auth）
└── 配置菜单（如需要）
```

## 联调验证

```
Step 1: 后端验证
├── go build ./...（编译通过）
├── go test ./...（测试通过）
├── API 工具测试（curl/Postman）
└── 确认响应格式正确

Step 2: 前端验证
├── npm run build（构建通过）
├── 页面能正常访问
├── CRUD 操作正常
└── 错误处理正常

Step 3: 端到端验证
├── 创建 → 列表显示
├── 编辑 → 数据更新
├── 删除 → 列表移除
└── 刷新 → 数据持久
```

## 开发顺序

禁止跳着写：

Go: 必须先写后端 Model → Repository → Service → Handler
Python: 必须先写 Model → Service → Adapter → CLI/API
前后端项目: 后端 API 测试通过后再写前端
Vue: 必须先写 types → api → composable → 组件 → 页面

## 故障排查

### Bug 定位 5 步法

1. **复现**: 确认能稳定复现，记录复现步骤
2. **定位范围**: 前端？后端？数据库？最近改了什么？
3. **深入分析**: 读代码、加日志、分析数据流
4. **修复**: 最小改动修复
5. **验证**: 复现步骤不再触发，加回归测试

### 常见错误速查

| 类型   | 错误               | 修复               |
| ------ | ------------------ | ------------------ |
| 编译   | import 错误        | 修正路径或安装依赖 |
| 编译   | 类型错误           | 修正类型或转换     |
| 运行   | nil pointer        | 加 nil 判断        |
| 运行   | index out of range | 加长度判断         |
| 数据库 | 连接失败           | 修正连接串         |
| 数据库 | 慢查询             | 加索引             |
| API    | 404                | 注册路由           |
| API    | 500                | 修复 panic         |
| API    | 超时               | 加超时/缓存        |

### 日志分析 checklist

- [ ] 找到错误发生时间点
- [ ] 找到错误堆栈
- [ ] 找到请求上下文（user_id, trace_id）
- [ ] 往前找相关日志
- [ ] 往后找后续处理

### 调试技巧

加日志：`log.Printf("[DEBUG] user_id=%d, req=%+v", userID, req)`

二分定位：100 行代码出 bug？在 50 行加日志，确定前半还是后半，重复直到定位。

最小复现：剥离无关代码，构造最小复现 case。

### 性能问题排查

```
慢？
├── 是数据库？→ 慢查询日志 / EXPLAIN / 加索引
├── 是代码？→ 加耗时日志 / pprof / 优化算法
└── 是网络？→ 检查依赖超时 / 加缓存
```
