# G-02: 编码规范

## 命名

> 详见 G-09 命名规范

禁止 tmp/data/info 等模糊命名。

## 复杂度限制

- 函数长度 ≤50 行，单行长度 ≤120 字符
- 嵌套深度 ≤3 层，函数参数 ≤4 个
- 圈复杂度 ≤10
- .go 文件 ≤600 行，.py 文件 ≤500 行，Vue 组件 ≤500 行（与 G-03 一致，完整业务模块可到 500 行）

## DRY

出现 2 次以上相同逻辑 → 提取为函数/组件

## 时区

- 数据库: UTC 存储
- Go: `time.Time` 默认 UTC
- Python: `datetime.now(timezone.utc)`
- API: ISO 8601 格式

## 日志

| 级别  | 场景       |
| ----- | ---------- |
| INFO  | 正常业务   |
| WARN  | 可恢复异常 |
| ERROR | 异常失败   |

内容全英文，禁止记录密码、Token、完整手机号。

## 注释

解释"为什么"，而非"是什么"。复杂逻辑必须注释。

## Go 特定

- 用 `gofmt` 格式化
- 错误处理: `if err != nil` 立即处理
- 并发: 用 `context` 控制生命周期
- 禁止 `interface{}` 滥用、`panic`

## Python 特定

- 用 `black` 格式化
- 类型注解: 参数/返回值必须标注
- 异步: 用 `async/await`
- 禁止 `*` import、裸 `except`

## 前端特定

- Vue: Composition API + `<script setup>`
- React: Function Components + Hooks
- TS: 严格模式，禁止 `any`
- 样式: Tailwind CSS
- 禁止内联样式、魔法数字

## TypeScript 严格模式

- `strict: true`, `strictNullChecks: true`, `noImplicitAny: true`
- 函数参数/返回值必须标注类型
- 禁止使用 `any`，使用 `unknown` + 类型守卫
- 可选链 `?.` 替代 `&&` 检查
- 空值合并 `??` 替代 `||`

## 分层架构

| 层         | 职责                 | 禁止             |
| ---------- | -------------------- | ---------------- |
| Handler    | 参数绑定、校验、响应 | 业务逻辑、SQL    |
| Service    | 业务逻辑、事务       | 操作 HTTP 上下文 |
| Repository | 数据库 CRUD          | 业务判断         |
| Model      | 数据结构             | 业务方法         |

DTO: Request/Response 分离，禁止直接返回 GORM Model

## DTO 与响应裁剪

- 禁止直接返回 GORM Model / 数据库全量字段，必须通过 Response DTO 裁剪
- 每个接口定义独立的 Response DTO，只包含前端需要的字段
- 列表接口和详情接口用不同 DTO（列表精简，详情完整）
- 敏感字段（密码、Token、is_deleted 等）禁止出现在任何响应中
- Repository 层配合 DTO 用 `Select()` 指定字段，避免 `SELECT *`

```go
// 正确 - 按需返回
type UserListItem struct {
    ID       uint   `json:"id"`
    Username string `json:"username"`
    Status   int    `json:"status"`
}

type UserDetail struct {
    ID         uint      `json:"id"`
    Username   string    `json:"username"`
    Email      string    `json:"email"`
    Status     int       `json:"status"`
    CreateTime time.Time `json:"create_time"`
}

// 错误 - 直接返回 Model
c.JSON(200, Response{Data: user})  // user 是 GORM Model，会暴露全部字段
```

## API 设计

> 详见 G-12 API 设计规范，错误码详见 G-10

核心要点：RESTful 路由（名词复数、kebab-case）、统一响应 `{code, message, data}`、分页 `page + page_size`、错误码定义在 `pkg/errcode` 禁止硬编码。

参数校验：所有入参必须校验类型和格式，必填参数必须校验存在。

## 安全规范

> 详见 G-05 安全规范

核心要点：输入白名单验证、参数化查询防 SQL 注入、JWT ≤24h + HTTPS、禁止硬编码密钥、日志脱敏、最小权限原则、CORS 白名单。

## 质量保障

> 详见 G-06 测试规范

核心要点：核心逻辑覆盖率 ≥80%、缓存防穿透/击穿/雪崩、API P99 < 200ms。
