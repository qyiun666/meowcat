# G-01: 开发工作流

## 需求确认

改代码前必须：

- 复述需求（用自己的话描述理解）
- 识别边界（明确什么做、什么不做）
- 列出假设（需求不明确的地方请用户确认）
- 评估风险（标注 L1/L2/L3 级别）

**禁止假设用户意图直接开干**

## 技术方案（L2/L3 必须）

```
## 技术方案
### 目标
一句话说明要解决什么问题

### 方案
1. 改动哪些文件
2. 新增哪些文件
3. 数据流怎么走
4. 错误怎么处理

### 风险
- 可能影响哪些现有功能
```

用户确认后再实施。

## 渐进式构建

原则：每步产出必须是可运行/可编译的

禁止：

- 一次改 5+ 个文件再一起验证
- 写 TODO/FIXME 占位

正确流程：

1. 改 1 个文件 → 编译通过
2. 改调用方 → 编译通过
3. 跑测试 → 全部通过
4. 再改下一个

## 自我审查 checklist

```
□ 能编译/通过类型检查
□ 所有 import 能正确解析
□ 没有占位代码（TODO/FIXME/xxx）
□ 错误都处理了（没有裸 err）
□ 没有死代码
□ 边界条件处理了（空值、越界）
□ 没有 SQL 注入风险
□ 没有硬编码密钥
□ 输入都校验了
□ 改了 API 同步改了所有调用方
□ 没有破坏现有功能
```

## 错误恢复

AI 发现自己写错时：

1. 立即停止后续操作
2. `git diff` 查看当前改动
3. `git checkout --` 回滚错误文件
4. 重新读取正确代码
5. 修正后重新验证

## 防幻觉 checklist

写代码前：

- [ ] 字段名 → 查 Model/数据库
- [ ] API 函数 → 查 api/ 目录
- [ ] import 路径 → 确认文件存在
- [ ] 函数签名 → 找到定义确认

写代码后：

- [ ] 所有字段真实存在
- [ ] 所有 import 能解析
- [ ] 所有函数调用参数正确

## 验证流程

Go:

```bash
go build ./... && go vet ./... && go test ./...
```

Python:

```bash
python -c "import meowagent" && pytest -q && ruff check .
```

Vue/前端:

```bash
npx vue-tsc --noEmit && npm run build
```
