# P-01: MeowAgent 项目导航

> 每个新会话启动时自动注入。先读 `docs/README.md` 再动手。
> 改代码前读 [P-02](P-02-MeowAgent开发哲学.md) 了解开发哲学。

## 第一步: 文档导航

启动后先读 **[docs/README.md](docs/README.md)**，了解有什么文档。

**第二步：读当前计划。** 去 `.qoder/plans/` 看有无活跃 plan，有则 `read_file` 全文。计划是执行权威源，`docs/v{version}/` 是事后交付物。

如果 plans/ 下有多个计划，以最新修改时间为准。

## 架构文档（单点真相）

修改任何代码前，**必须先读**对应架构文档：

| 要看什么                     | 读这个                               |
| ---------------------------- | ------------------------------------ |
| meowcat 框架层架构、四层抽象 | `docs/架构/00-meowcat-框架架构.md`   |
| meowagent 应用层架构、闭环   | `docs/架构/01-meowagent-应用架构.md` |
| 从零构建应用接入             | `docs/架构/02-应用层接入指南.md`     |

## 版本文档目录

meowcat 和 meowagent 各自独立维护版本记录：

```
docs/meowcat/v1.0.0/
├── README.md    ← 该版本总览 + 子版本进度
├── design.md    ← 架构设计（新功能、接口、数据流）
├── tasks.md     ← 任务拆解 + 进度跟踪 + 验收清单
└── review.md    ← 审查记录 + 关键决策 + 遇到的问题

docs/meowagent/v0.5.32/
├── README.md    ← 同上
├── design.md
├── tasks.md
└── review.md
```

新版本设计前先读 [docs/IDEAS.md](docs/IDEAS.md) 寻找灵感。想法纳入设计后从 IDEAS.md 删除。

## 协作模式

```
新功能开发:
  会话1: 读架构 → 产出设计文档到 docs/meowcat/v{version}/ 或 docs/meowagent/v{version}/ → 结束
  会话2: 读设计文档 → 按文档开发 → 结束
  会话3: 读设计文档 → 审查/提意见 → 结束

Bug修复:
  读 `docs/架构/01-meowagent-应用架构.md` §11 "Bug定位速查" → 定位闭环 → 读对应文档 → 修
```

## 关键约束

- 每个会话只做一件事（设计/开发/审查，不混）
- 关键决策必须写回设计文档，不能只留在会话记忆里
- 架构文档是活文档，改代码后发现架构变了要同步更新

## 本专项约束

- 计划最后一个子版本完成后：移入 `docs/plans/` 归档，从 `.qoder/plans/` 删除
- **会话结束前自动更新版本号**：meowagent 版本需改两处：`pyproject.toml` version + `meowagent/cli/commands/system.py` VERSION。meowcat 版本独立管理（见 `meowcat/pyproject.toml`），`meowcat/__init__.py` 从其自身的 `pyproject.toml` 动态读取。两个包版本号不再同步。
- **meowcat 独立测试**：`cd meowcat && pytest tests/` 可独立跑，零 meowagent 依赖
